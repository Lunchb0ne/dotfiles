# AGENTS.md — Dotfiles Repo Context

This is a [chezmoi](https://chezmoi.io/)-managed dotfiles repository.
The source directory is `~/.local/share/chezmoi/` and the destination (target)
is `$HOME`.

## Core chezmoi commands

| Command | Purpose |
|---------|---------|
| `chezmoi add <target>` | Start managing a file: copies target→source and adds to state |
| `chezmoi forget <target>` | Stop managing a file: removes from source state, leaves target on disk |
| `chezmoi apply` | Sync source→target (apply changes) |
| `chezmoi diff` | Show diff between source state and target (live) files |
| `chezmoi status` | Show which files differ between source and target |
| `chezmoi managed` | List all currently managed targets |
| `chezmoi re-add` | Re-copy modified target files into the source state |
| `chezmoi merge <target>` | Three-way merge between source, target, and destination (INTERACTIVE — avoid) |
| `chezmoi chattr <attr> <target>` | Change file attributes (template, executable, private, etc.) |
| `chezmoi git -- <cmd>` | Run git commands inside the chezmoi repo |

**Golden rules:**
- ALWAYS use `chezmoi add` / `chezmoi forget` to manage files — never cp or link manually
- ALWAYS use `--force` with `chezmoi forget` to skip interactive prompts
- NEVER use `chezmoi merge` in non-interactive (TTY-less) environments — it requires `/dev/tty`
- After editing a live file, run `chezmoi add <file>` to sync it back to the source state
- After editing a source file, run `chezmoi apply <file>` to push to the target

## Status codes (from `chezmoi status`)

| Code | Meaning |
|------|---------|
| ` ` (space) | No change |
| `A` | Entry was created since last chezmoi write |
| `D` | Entry was deleted |
| `M` | Entry was modified |
| First column | Difference between last written state and actual state |
| Second column | Difference between actual state and target state (what `apply` would do) |

## `.chezmoiignore`

The `.chezmoiignore` file in the source root lists patterns that chezmoi should
NOT manage. Patterns match against target paths (not source paths). Files
matching these patterns are excluded from `chezmoi status`, `add`, and `apply`.

Currently ignored:
- `AGENTS.md`, `README.md` — repo-level docs, not dotfiles
- `.config/niri/colors.kdl` — generated by matugen
- `.config/niri/dms/*.kdl` (auto-generated subset) — overwritten by DMS on restart
- `.config/mango/dms/*.conf` — overwritten by DMS on restart

## File attributes (`chezmoi chattr`)

| Attribute | Prefix | Effect |
|-----------|--------|--------|
| `empty_` | filename | Keep file even when empty (normally empty files are removed) |
| `executable_` | filename | Set executable bits in target |
| `private_` | filename | Clear group/world permissions |
| `template` | `.tmpl` suffix | Interpret as Go template |
| `once_` | filename (scripts) | Run script only if never run successfully before |
| `onchange_` | filename (scripts) | Run script only when contents change |
| `before_` / `after_` | filename (scripts) | Order scripts relative to other operations |

## Chezmoi Git

All git operations go through `chezmoi git` for safety:
```bash
chezmoi git status
chezmoi git diff
chezmoi git commit -m "message"
```

The chezmoi repo's working directory IS the source directory. Changes to source
files are git-tracked changes. Changes to target (live) files must be synced
via `chezmoi add` before they appear in git.

## Anti-patterns

- DO NOT manually `cp`, `ln`, `mv`, `rm` files to/from the source directory
- DO NOT run `git` commands directly in `~/.local/share/chezmoi/` — use `chezmoi git`
- DO NOT use `chezmoi merge` or `chezmoi merge-all` (requires TTY)
- DO NOT track DMS auto-generated files (see `.chezmoiignore`)
